# 原生多模态识图 —— 真机/桌面测试步骤与要点

> 对应分支: `feat/native-multimodal`
> 功能: 支持识图的对话模型可把用户图片/截图**当轮直发**给模型完成识图，替代原来的「旁白转述」；未开启的原模型行为完全不变。

## 一、前置条件

1. 需要一个**真正支持图片输入**的多模态对话模型，且走 OpenAI 兼容 `/v1/chat/completions`（`image_url`）或 Gemini 多模态协议。
   - 云服务示例：OpenAI `gpt-4o`、通义 `qwen-vl-max`（通过 DashScope compatible-mode）、`glm-4v` 等。
   - 本地示例：LM Studio 里加载一个视觉模型。
   - ⚠️ 纯文本模型（如 DeepSeek 官方 API）即使勾选「支持识图」也无法识图，务必自行确保模型支持图片。
2. 拿到对应平台的构建产物（见文末「构建与验证」）。

## 二、测试步骤

### 1. 配置模型并开启「支持识图」

1. 启动应用 → 进入 **设置 → 大模型管理**（`SettingsLlmProviders`）。
2. 新增或编辑一个多模态对话模型：
   - 提供商选 `OpenAI 兼容` / `Gemini` / `LM Studio（本地）`；
   - 填对 `API 地址` 与 `模型名称`；
   - 在表单中**勾选「支持识图（原生多模态）」**。
3. 把该模型分配为 **Chat 模型**（核心对话模型）。
   - 提示：角色分配与热切换会立即生效，`switch_llm` 会自动重建槽位。

### 2. 真机测试一：桌面截图识图

1. 聊天输入框点击**截图按钮**，框选桌面区域并确认（走 `send_chat_message(text, screenshotBase64)`）。
2. 发送后观察：
   - **成功**：直接收到基于图片内容的 AI 回复（如询问桌面内容、图片里的文字等）；历史**不再出现**「旁白」长文本转述。
   - **回退**：若图片压缩失败或模型协议不支持，会静默回退到旁白转述（体验上仍能识图，只是多一次旁白）。
3. 并发测试：截图 + 附带文字询问，确认模型能同时理解图片与所附文字。

### 3. 真机测试二：图片文件投喂

1. 拖入 / 选择一张本地图片文件（走 `feed_image(path)`）。
2. 发送后观察：
   - **成功**：直接收到基于图片内容的回复；
   - 历史里**只新增一条轻量文本提示**（如「用户发来一张图片，请你直接查看」），**未写入冗长转述**——确认图片本身不持久化进角色记忆。

### 4. 回归测试：未开启「支持识图」的模型

1. 把 Chat 模型切回一个**未勾选**「支持识图」的模型（或纯文本模型）。
2. 再次执行截图 / 图片投喂，确认仍走**原旁白转述**路径（行为与更新前一致）。

## 三、验收要点（容易踩的坑）

1. **图片当轮发送、不写记忆**：为实现「图片缓存率/上下文占用」目标，原生识图只把压缩图片拼进**当轮** LLM 请求，不写入 `role.memory`。跨轮再次提问时，模型不会“记住”上一轮的图（需重新发图）。
2. **图片会自动压缩**：统一等比缩放到最长边 ≤ 1024px、转 JPEG（质量 85），透明图压到白底。超大图、半透明 PNG 会先被压缩再发送——这既是省 token，也避免部分 OpenAI 兼容视觉端点对 WebP/PNG 解析不稳。
3. **kimi_code / codex 不受支持**：这两个 provider 有独立实现、暂不支持在对话消息里注入图片，即使勾选「支持识图」也**仍走旁白转述**。代码已做 `is_genai_multimodal_capable()` 门控。
4. **工具调用（tool loop）的边界**：图片只在当前这一轮消息里；若本轮触发了 `character_switch`（切换对话角色），新角色重建的上下文里不包含这张图（属于边缘情况，可接受）。
5. **错误回退**：图片解码/压缩失败会自动回退到旁白转述，不会卡在「思考中」或直接报错。
6. **模型能力自测建议**：首次使用前，可在「大模型管理 → 测试」里先发一条文本确认模型连通；再发一张图走实机路径，若回复内容与图片明显相关即通过。
